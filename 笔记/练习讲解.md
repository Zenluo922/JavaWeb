# Servlet 会话练习 —— 登录 + 记住我 + 登录墙 + 退出（答案与讲解）

> 对应 `LoginServlet.java` / `IndexServlet.java` / `LogoutServlet.java`
> 核心考点：**Session 读写与失效、Cookie 增删、重定向 vs 转发、URL 编码**

## 整体流程

```
浏览器                        服务器
  │  GET /login                 │
  │ ────────────────────────────>│ LoginServlet.doGet   画登录表单（顺带回显记住的用户名）
  │  POST /login (用户名/密码/记住我)
  │ ────────────────────────────>│ LoginServlet.doPost
  │                              │   ├─ 成功：Session 存 loginUser + 写/删 Cookie + 重定向 /index
  │                              │   └─ 失败：req 存 msg + 转发回 /login（地址栏不变）
  │  GET /index                 │
  │ ────────────────────────────>│ IndexServlet.doGet   登录墙：Session 里没有 loginUser 就踢回 /login
  │  GET /logout                │
  │ ────────────────────────────>│ LogoutServlet.doGet  Session 失效 + 清 Cookie + 重定向 /login
```

## 一、LoginServlet —— 登录页 + 登录处理

### TODO(1) 从 Cookie 回显用户名（doGet）

```java
String username = "";
Cookie[] cookies = req.getCookies();
if (cookies != null) {                              // 第一次访问浏览器不带任何 Cookie，数组是 null
    for (Cookie c : cookies) {
        if ("rememberUser".equals(c.getName())) {   // Cookie 只有遍历查找，没有按名字取的方法
            username = URLDecoder.decode(c.getValue(), "utf-8");  // 写入时编码过，读出来要解码
            break;
        }
    }
}
```

**讲解：**
- `req.getCookies()` 返回的是**整个网站所有 Cookie**（不只你这个应用写的），所以必须遍历按 `getName()` 找，**没有 `getCookie("名字")` 这种方法**。
- 首次访问浏览器一个 Cookie 都没带，`getCookies()` 返回 **null**，不判空直接 for 会空指针——这是本题第一个易错点。
- 值当初是 `URLEncoder.encode` 存的（Cookie 值不允许中文/特殊字符），读出来必须 `URLDecoder.decode` 还原，编码解码用的字符集要一致。

### TODO(2) 读取参数并校验（doPost）

```java
String username = req.getParameter("username");
String password = req.getParameter("password");
String remember = req.getParameter("remember");     // checkbox：勾了才有值 "on"，没勾就是 null

boolean ok = username != null
        && password != null
        && password.equals(USERS.get(username));   // USERS 里查不到时 get 返回 null，equals 为 false
```

**讲解：**
- `Map.of("admin","123456","user","123456")` 假装数据库；`USERS.get(用户名)` 查无此人返回 null。
- 把 `password` 放在 `equals` 的**左边**、`USERS.get(username)` 放右边：就算用户不存在（右边是 null），`equals(null)` 也只是返回 false，不会空指针。
- `remember` 是 checkbox，**没勾选时浏览器根本不提交这个参数**，所以 `getParameter("remember")` 是 null——后面判断"勾没勾"就是靠这个。

### TODO(3) 登录成功分支

```java
// 1. 用户名存入 Session
req.getSession().setAttribute("loginUser", username);

// 2. 处理"记住我" Cookie
Cookie c = new Cookie("rememberUser", URLEncoder.encode(username, "utf-8"));
if ("on".equals(remember)) {
    c.setMaxAge(7 * 24 * 60 * 60);   // 勾了：7 天 = 604800 秒
} else {
    c.setMaxAge(0);                  // 没勾：同名 + 0 秒 = 让浏览器立刻删掉旧 Cookie
}
c.setPath("/");                      // 写和删时路径必须一致，否则删不干净
resp.addCookie(c);                   // Cookie 是通过响应头 Set-Cookie 发给浏览器的

// 3. 重定向到 /index
resp.sendRedirect(req.getContextPath() + "/index");
```

**讲解：**
- `req.getSession()`：没有 Session 就**顺手创建**一个并返回，登录成功这里正需要新 Session，直接用无参版本。
- Cookie 存中文必须先 `URLEncoder.encode`，否则响应头里出现非法字符直接报错——和 TODO(1) 的 decode 一来一回收支平衡。
- **"删除" Cookie 的唯一办法**：服务器没法命令浏览器删文件，只能再发一个**同名、`setMaxAge(0)`、同路径**的 Cookie 覆盖掉，浏览器收到后立刻清掉。路径不一致浏览器会当成两个不同 Cookie，旧的删不掉。
- 重定向用 `sendRedirect`，地址要拼上 `req.getContextPath()`（应用部署路径），否则部署名不是 `/` 时会 404。

### TODO(4) 登录失败分支

```java
req.setAttribute("msg", "用户名或密码错误");
req.getRequestDispatcher("/login").forward(req, resp);
```

**讲解：**
- 这里**必须用转发**：`setAttribute` 存的数据只活在本**一次请求**里，转发是服务器内部把 req/resp 原封不动交给 `/login`，**同一次请求**，所以 doGet 里 `getAttribute("msg")` 取得到。
- 如果改成重定向：浏览器发起的是**第二次新请求**，新 req 里什么属性都没有，错误提示会丢——这就是"转发带数据、重定向不带"的原因，不是背规则，是请求次数决定的。

## 二、IndexServlet —— 登录墙

### TODO(5) 登录检查

```java
HttpSession session = req.getSession(false);   // 只查不建！
if (session == null || session.getAttribute("loginUser") == null) {
    resp.sendRedirect(req.getContextPath() + "/login");
    return;                                    // 不 return 会继续往下执行，欢迎页照样输出
}

String loginUser = (String) session.getAttribute("loginUser");
PrintWriter out = resp.getWriter();
out.println("<h2>欢迎你，" + loginUser + "</h2>");
out.println("<a href='logout'>退出登录</a>");
```

**讲解：**
- **本题真正想让你记住的点**：`getSession()` 没有也会新建一个 Session（浪费内存），只想确认"登录了没"应该用 `getSession(false)`——没有就返回 null，绝不新建。
- `session == null`（压根没 Session，比如刚开浏览器）和 `getAttribute == null`（有 Session 但没登录过，比如登录墙页先于登录被访问过）是两种情况，都要拦。
- `sendRedirect` 只是"告诉浏览器去跳"，**后面的代码还会继续执行**，必须 `return` 手动切断，否则没登录的人也能看到欢迎页内容。
- 需要 import：`jakarta.servlet.http.HttpSession`、`java.io.PrintWriter`。

## 三、LogoutServlet —— 退出登录

### TODO(6) 退出

```java
// 1. 让当前 Session 立刻失效
HttpSession session = req.getSession(false);
if (session != null) {
    session.invalidate();        // 里面的 loginUser 属性连同 Session 一起销毁
}

// 2. 清掉 rememberUser Cookie（同名 + setMaxAge(0) + 路径和写时一致）
Cookie c = new Cookie("rememberUser", "");
c.setMaxAge(0);
c.setPath("/");
resp.addCookie(c);

// 3. 回登录页
resp.sendRedirect(req.getContextPath() + "/login");
```

**讲解：**
- `invalidate()` 是让 Session 立刻失效的专用方法，比 `removeAttribute("loginUser")` 删得更彻底（连 Session 本身都不留）。销毁后再用这个 Session 会抛 `IllegalStateException`。
- 这里也用 `getSession(false)` + 判空：没登录的人手贱访问 `/logout`，没必要为他新建一个 Session 再销毁。
- 清 Cookie 三要素：**同名、setMaxAge(0)、同路径**，缺一个都删不掉——和 TODO(3) 前后呼应。

## 四、两张对照表（面试高频）

### 重定向 sendRedirect vs 转发 forward

| | 重定向 `sendRedirect` | 转发 `forward` |
|---|---|---|
| 谁去跳 | 浏览器发起第二次请求 | 服务器内部转手，浏览器不知情 |
| 请求次数 | 2 次 | 1 次 |
| 地址栏 | **变**成新地址 | **不变** |
| 域对象数据 | 丢（新请求，req 属性取不到） | 能带（同一个 req） |
| 能否跳外站 | 能（写完整 URL） | 不能（只能站内） |
| 典型场景 | 登录成功进首页、退出回登录页 | 登录失败带回错误提示 |

> 记忆钩子：**地址栏要变 → 重定向；要带 req 里的数据 → 转发**。登录成功两个都不要带数据所以要变（防表单重复提交），登录失败要带 msg 所以不变。

### Cookie vs Session

| | Cookie | Session |
|---|---|---|
| 存在哪 | **浏览器**端（随每个请求带来带去） | **服务器**端内存 |
| 安全性 | 用户可见可改，别放密码 | 用户拿不到内容，放登录状态正合适 |
| 生命周期 | `setMaxAge` 自己定（7 天） | 默认 30 分钟不活动 / `invalidate()` 立刻销毁 |
| 大小限制 | 单个约 4KB，数量也有限制 | 只受服务器内存限制 |
| 本练习中的角色 | "记住我"——记**用户名**这种无所谓安全的小东西 | 登录墙——记**登录状态**这种不能暴露给浏览器的东西 |

## 五、易错点 Checklist（自查）

- [ ] `req.getCookies()` 判空了吗？（首次访问是 null）
- [ ] 遍历 Cookie 是按 `getName()` 比对，而不是想当然有按名取的方法？
- [ ] Cookie 值写时 `encode`、读时 `decode`，字符集一致？
- [ ] 删 Cookie 时**同名 + setMaxAge(0) + 同路径**三件事都做了？
- [ ] 查登录状态用的是 `getSession(false)` 而不是 `getSession()`？
- [ ] `sendRedirect` / `forward` 之后 `return` 了吗？
- [ ] 重定向地址拼了 `req.getContextPath()` 吗？
- [ ] checkbox 没勾时 `getParameter` 是 **null** 而不是空串？
